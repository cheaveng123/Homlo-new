- Pending rows are unlimited: boost.create and paid-plan subscription.purchase insert a pending payments row (and a failed payment_webhook_events row) on every call, before verification, with no rate limit or per-user cap. Fail-closed payments do not stop this.

They match today (pro 1999, enterprise 49900). A mismatch makes every purchase fail.
- Plans have no visible expiry: homlo_upsert_subscription sets current_period_end but nothing read so far checks it, and the gateway's Pro check is plan = 'pro' and status = 'active'. Unknown whether a scheduled job expires subscriptions.
- Gateway has no rate limit; every request makes a Supabase /auth/v1/user call, and valid tokens also make a resolve-account RPC. getVerifiedUser runs outside the try block, so a timeout or network error there is not caught by the gateway's own handler. rpc() and rest() log full database error bodies with console.error.
- Gateway inputs that skip tRPC's zod: profile.upsert, employer.save-job and others pass payload fields straight to RPCs. messaging.messages passes any numeric limit (unbounded), messaging.report has no length limit on reason or details, and homlo_save_job has no length caps, no latitude/longitude range checks, and accepts any banner_image string.
